### Ruling

SHIP:    OBJ-map-debugger-4 — light-theme topbar button contrast fix in
         `docs/brand.css`. No rung-1 or rung-2 candidate existed this
         sitting, so nothing pre-empted the docket. Among rung-3/4
         candidates, this is the cleanest rung-4 case on the board — "the
         audience cannot read what is already there," literally: near-white
         text on a white button, a total, not partial, loss of legibility
         for every topbar action (Solaire, Methodology, GitHub, theme
         toggle) in light mode. It has now been independently confirmed
         live twice (2026-08-04 screenshot, and this sitting's re-check),
         the root cause was pinned to an exact cascade conflict
         (`docs/brand.css:32-36` vs `docs/style.css:113-115`, equal
         specificity, brand.css wins on load order), it is S, reversible,
         and touches one file with a single additive rule. Ranked above
         OBJ-frontend-engineer-3 (also rung-4, topbar overflow) because the
         contrast bug is a 100%-of-users legibility failure in light mode
         versus a viewport-dependent one, and above OBJ-map-debugger-1
         (dead mailto) because a broken feedback channel is lower-severity
         than an unreadable primary navigation bar. Verified before shipping
         that `docs/brand.css` and `solar/brand.css` are two independently
         loaded files (byte-identical today, not a shared runtime include),
         so this fix cannot affect Atlas Solar's chrome — the risk noted on
         the Board ("must not break Solar's topbar") does not apply as
         written and is now closed.
